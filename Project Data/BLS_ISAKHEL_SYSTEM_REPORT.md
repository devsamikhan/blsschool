## 3. System Architecture

### 3.1 The "Institutional Nexus" Layer
At the core of BLS Isakhel is the **Central Data Manager** ([lib/DataManager.ts](file:///e:/blsschool-main%20-%20Copy/src/lib/DataManager.ts)).
- **Relational Integrity**: Automatically synchronizes data across disjointed collections (e.g., student deletion automatically cleans up class rosters and teacher assignments).
- **ID Protocol**: Collision-proof alphanumeric 128-bit ID generation with role-based prefixes (`PRIN-`, `TCH-`, `STU-`).

### 3.2 Real-Time Synchronization
The platform utilizes a **Global Event Bus**. Any change made in one browser tab (e.g., an Admin updating a student) is instantly broadcasted to all other open tabs (e.g., the Teacher's view) without a page refresh.

## 4. Module Breakdown

### 4.1 Public Sector (The Front Door)
- **Cinematic Home**: High-fidelity marketing presence.
- **Unified Public Tracker**: A single portal where applicants can track **Admissions** or **General Inquiries** using a Tracking ID.

### 4.2 Administrative Fortress (The Command Center)
- **Identity & Access**: RBAC (Role-Based Access Control) to manage 7 distinct institutional roles.
- **Inventory Control**: Real-time tracking of institutional assets.
- **Bulk Operations**: Mass data ingestion engine.

### 4.3 Principal's Command Hub
- **Signal Broadcast**: School-wide announcement system with role and class-based targeting.
- **Academic Heatmaps**: Visual reports on class performance and attendance.
- **Financial Audit**: High-level overview of revenue leakage and collected dues.

### 4.4 Academic Delivery (Teachers & Students)
- **Feedback Loop**: Teachers create homework; students submit; teachers grade with rich feedback. All synced in real-time.
- **Attendance Protocol**: Secure daily marking system.

### 4.5 Guardian Gateway (Parent Portal)
- **Direct Monitoring**: Permanent registry-bound link between Parent and Student identities.
- **Instant Transparency**: Real-time access to child’s attendance, results, and fee status.

- **Guarded Routes**: Protected by the `RequireAuth` higher-order component.
- **Data Sanitization**: API layer automatically strips passwords and sensitive metadata before delivering to the UI.
- **Strict Typing**: Zero `any` types across mission-critical modules.

## 6. Developer Onboarding (Setup)
To run the system locally:

1.  **Dependencies**: `npm install`
2.  **API Core**: `npm run dev:api` (Runs local database on port 3001)
3.  **UI Engine**: `npm run dev` (Runs Vite on port 5173 or 8080)
4.  **Full Suite**: `npm run dev:all` (API + UI concurrently)
